## 2026-10-17 chromedp latest breakage

chromedp v0.21.0 does not compile the existing cmd/screenshot (outside T0 scope). Exact errors from make typecheck:

cmd/screenshot/main.go:108:3: too many arguments in call to chromedp.Run, have (context.Context, Action, Action, Action, Action, Action[[]byte]) want (context.Context, chromedp.Action[T])
cmd/screenshot/main.go:109:48: undefined: chromedp.ByID
cmd/screenshot/main.go:111:30: too many arguments in call to chromedp.CaptureScreenshot, have (*[]byte) want ()

v0.21.0 is an API rewrite: Run takes one action (actions must compose), ByID is gone, CaptureScreenshot returns the bytes. Migrating cmd/screenshot/main.go to that API belongs to whoever owns cmd/. Per the latest-first fallback rule T0 pins the newest chromedp that still compiles the tree (bisect below) and the bump to v0.21.0 follows once cmd/screenshot is migrated.

First bisect attempt was invalid: it ran with CGO_ENABLED=0, under which mattn/go-sqlite3's cgo-tagged files drop out and internal/store fails with undefined sqlite3.Error/ErrConstraintUnique/ErrConstraint, masking the chromedp result. Redone with CGO_ENABLED=1 -tags sqlite_fts5.

Corrected bisect: v0.20.1, v0.19.1, v0.18.0 all show the same cmd/screenshot breakage as v0.21.0 (API rewrite landed by v0.18.0). v0.17.1 and v0.16.0 fail to compile chromedp itself against the cdproto that go get keeps selected under MVS (cdproto v0.157.x removed identifiers chromedp's kb package and query internals reference: input.KeyDown/KeyUp/KeyChar/ModifierShift gone, struct literals int64 vs *int64). chromedp v0.16.0 still has the old API (Run(ctx, actions ...Action), ByID, CaptureScreenshot(res *[]byte)) and pins cdproto v0.0.0-20260714215040-dc233986426f, so the explicit pair chromedp@v0.16.0 + cdproto@v0.0.0-20260714215040-dc233986426f compiles ./cmd/screenshot.

Resolution: chromedp pinned at v0.16.0 (newest version-pair that compiles the existing tree, one minor above the previous v0.15.1). The v0.21.0 bump belongs to the cmd/screenshot migration (folded into task C2): Run composes one action, ByID is gone (use a selector option), CaptureScreenshot returns the bytes. Every other canon dependency sits at its verified latest.

### chromedp v0.21 migration map for C2 (verified against v0.21.0 source, no re-bisect needed)

Old API in cmd/screenshot/main.go today, new API in v0.21.0:

- chromedp.Run(ctx, action1, action2, ...) error became generic Run[T any](ctx, Action[T]) (T, error), single action. For the error-only call sites the drop-in is Do(ctx, steps ...Action[Void]) error; Steps(steps ...Action[Void]) Action[Void] replaces the old Tasks type and stops at the first error.
- chromedp.ByID is gone. Selectors are now Selectable values: WaitVisible("#quote-list", chromedp.ByID) becomes WaitVisible(chromedp.ID("quote-list")) or WaitVisible(chromedp.CSS("#quote-list")). WaitVisible[S Selectable](sel S, opts ...QueryOption) Action[Void].
- chromedp.CaptureScreenshot(&buf) became CaptureScreenshot() Action[[]byte]: the bytes come from Run's return value, and Steps discards its input's value, so capture cannot ride inside Do/Steps. Shape: run the setup actions with Do, then buf, err := chromedp.Run(ctx, chromedp.CaptureScreenshot()).
- Unchanged, no migration needed: DefaultExecAllocatorOptions, Flag, ExecPath, NewExecAllocator, NewContext, EmulateViewport, Navigate, Sleep.
- cdproto MVS constraint: chromedp v0.16.0 and v0.17.1 do not compile against cdproto v0.157.x (kb.go and query internals reference identifiers cdproto removed, int64 vs *int64 struct literals), and MVS keeps the highest selected cdproto, so downgrading chromedp alone cannot pick an intermediate version. The only path from the v0.16.0 pin is a straight jump to v0.18.0 or later with the migration above; v0.18.0 through v0.21.0 share the same breaking API.
