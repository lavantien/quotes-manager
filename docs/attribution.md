# attribution

Every third-party source the v2.0.0 canon pipeline mirrors or vendors, with each license grounded in the actual license text read from a physical file. Local readings are pinned by file sha256 and, for git mirrors, by the mirrored commit. Upstream readings are pinned by the sha256 of the fetched text and the fetch date, 2026-10-17.

## how the pipeline preserves notices

The sync pipeline keeps the license texts physically inside the mirrors. The internal/config defaults give bilara the keep regex ^(README\.md|LICENSE|LICENSE\.md|CONTRIBUTING\.md)$ and editions the keep regex ^(README\.md|LICENSE)$, while every other file in the mirror is pruned on each sync, so the license and readme files survive at the repo roots of both mirrors. The dpd mirror keeps provenance.json beside dpd.db recording the fetched tarball's sha256, size, tag, and fetch time, which ties any future license statement to the exact artifact that was fetched. The dpd license text itself is not part of the mirror, so this document is where that license is recorded.
